DiffLens architecture

DiffLens runs the same input cases through a legacy and a new-gen Java code base, each with its own tests, and shows the input cases where the two results differ. Read left to right.

1 · Get the code

Code bases

  • kravi519/LegacyCode (main)
  • kravi519/NewGenCode (main)
Each side has its own repo, branch or commit in the left panel. Both are a small pacs.008 payment app, laid out as MVC.
▼

source.py · resolve_source()

  1. Download a GitHub zip snapshot (token for private repos)
  2. Else the last download in .work/repos/
  3. Else the bundled copy in sample/legacy or sample/newgen
Result: a project folder for each side.
→
2 · Build and test each side

Shared input cases · sample/inputs/

  • pacs008.csv: 54 hand-written edge cases, each with an expected result
  • pacs008_bulk.csv: 500 generated cases, no expected result
  • XML messages in pacs008/ and pacs008/bulk/
▼ the same cases feed both sides
java_runner.py · run_suite() · both sides in parallel

Legacy

JDK 8 (javac --release 8)
1javac compiles src/main/java
2javac compiles src/test/java (its own tests)
3JUnit console launcher runs the tests
4Recorder prints RESULT|case|output
5JUnit XML is read by parse_reports()

New gen

JDK 21
1javac compiles src/main/java
2javac compiles src/test/java (its own tests)
3JUnit console launcher runs the tests
4Recorder prints RESULT|case|output
5JUnit XML is read by parse_reports()
Maven and Gradle projects work too. Compiled classes are reused while the sources, JDK and classpath stay the same.
→
3 · Compare

compare.py · compare()

Matches the two runs on the case id, so the two suites can be written separately.
  • Regression: passes on legacy, fails on new gen
  • Fixed: fails on legacy, passes on new gen
  • Changed: another status change
  • Output differs: same status, different output
  • Only in one run
  • Same
▼

difference_causes()

Groups the differing outputs by the words only one side produced (e.g. R49, INSTRID), so hundreds of bulk differences collapse into a few causes.
→
